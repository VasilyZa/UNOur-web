# UNOur Web

UNO 网页客户端。Svelte 5 + TypeScript + Vite，独立于 Go 后端的前端项目。

main 推送会由 GitHub Actions 执行真实 Go 后端测试、检查和 Docker 构建，成功后自动部署前端镜像。后端单独更新，SQLite 数据卷保持不变；服务端安装与回退方法见 [部署说明](https://github.com/chemsource/UNOur/blob/main/docs/deployment.md)。服务器地址、部署私钥和固定主机公钥存放在 Actions Secrets，仓库内不保存服务器密码。

## 开始

Node.js 22.12+，建议使用 Node.js 24 LTS。

```sh
npm ci
npm run dev
```

打开 http://localhost:5173，注册或登录账户后即可开始人机对战，也可创建或加入真人房间。所有游戏状态、身份与头像均由真实 Go 后端处理；不提供客户端试玩或模拟对局。前端运行和浏览器验收前都需要先启动后端。

## 连接 Go 后端

后端默认地址 `http://127.0.0.1:8088`，Vite 将 `/api` 代理到该地址。后端会验证浏览器的 Origin，开发时这样运行后端：

```sh
# 在 Go 后端目录执行
UNO_ALLOWED_ORIGINS=http://localhost:5173 make run
```

注册用户名为 3–24 个汉字、英文字母、数字、下划线或短横线，英文大小写不重复占用；密码限制为 **8–14 个字符（含边界）**。账户入口支持 PNG/JPEG 头像上传及恢复灰白默认头像。上传最多 2 MiB，后端会中心裁切并重编码。

大厅默认选择人机对战，可设置 1–9 名电脑玩家和简单、标准、困难或专家难度；服务端创建牌局后会直接发牌。电脑按已公开的出牌记录和局势搜索下一步，难度调整搜索预算，不代表胜率。人机局公开电脑的难度与风格，电脑手牌和决策记忆不会发送给前端。

创建房间和人机对战均可展开「自定义规则」：同色接牌、同数字接牌（至少一项）、+2/+4 混合叠加、禁后摸一张、连续反转转移罚牌、万能牌保留当前颜色、+4 质疑、质疑失败罚牌 2 倍、异色 +2 叠加。混合、异色与反转选项需开启罚牌叠加；质疑失败默认承担当前罚牌池的 1.5 倍，关闭质疑时倍率设置不生效。只开同数字时，万能牌指定颜色仍作为接牌例外。房间规则说明、手牌提示和选色面板均使用服务器返回的实际配置，规则保存在 SQLite，并沿用到下一局。

另可启用「摸牌后允许出任意手牌」，选择原有手牌中符合本局规则的牌；默认关闭，只允许出刚摸到的牌。每回合仍只能主动摸一张，可以选择跳过；罚牌摸牌后直接结束回合。

创建真人房间后可复制邀请链接给朋友；对方登录后加入，至少两人时房主可以开局。也可以输入区分大小写的房间号。同账户重新加入会恢复自己的身份，不会增加重复玩家。局中加入先观战并预约下一局；勾选“仅观战”或使用观战邀请链接不占座位。观战视图不展示任何玩家的手牌。

本局结束后显示再来一局的同意进度，所有仍参赛真人及下局预约者同意后自动发牌，电脑自动同意。参赛名单变化时重新确认。房间面板可复制玩家/观战邀请、报名或取消下局入座、退出和解散。主动退出按弃权处理，房主自动转交；关闭页面保留身份以便恢复。

后端运行在其他地址时：

```sh
cp .env.example .env.local
# 编辑 API_PROXY_TARGET，然后重新启动 npm run dev。
```

手机访问开发机的局域网地址时，后端 `UNO_ALLOWED_ORIGINS` 也要加入该完整地址，例如 `http://192.168.1.10:5173`；多个来源用逗号分隔。Vite 开发服务器默认监听所有网卡，仅用于开发。

人机与联机模式支持出牌、摸牌、跳过、+4 质疑、UNO 声明与漏喊罚摸；房间支持创建、加入、房主开局、局中邀请、观战、下一局预约、全员同意再来一局、退出弃权、房主转交和房主解散。当前后端只有 HTTP API，这版使用约 900ms 轮询；隐藏页面暂停轮询，返回后恢复。电脑行动完全由 Go 服务端驱动，前端只展示服务端状态。传输层可以独立替换为推送实现。

## 手机和交互

- 竖屏优先：对手在上、牌堆在中、手牌与操作在下；短屏收起次要说明。
- 手牌较多时原生横向滚动；点选后确认出牌，避免误触即出。
- 外观支持浅色、深色和跟随系统，偏好设置保存在当前浏览器；首屏加载即应用主题。
- UNO：剩一张牌时，立即点中央按钮或按空格键。输入框、打开的面板中不拦截空格。
- UNO 处罚使用后端窗口 ID 幂等上报；过早上报会延后重试。网络延迟可能影响两秒声明，以服务器收到请求的时间为准。
- 动效只用于反馈、牌的空间变化和面板进出，约 120–250ms。系统减少动态效果偏好或「轻柔动效」设置会移除位移动画。
- 使用 `dvh`、安全区边距、16px 输入字号，保留页面缩放；触屏不会触发悬停动效。

浏览器中的布局检查覆盖 320×568、360×780、390×844、430×932、平板与桌面。真实手机的刘海、浏览器工具栏、软件键盘和设备帧率仍需实机确认。

## 会话与请求

账户登录使用后端 HttpOnly Cookie，JavaScript 不读取账户会话令牌。房间凭证按账户标记保存在当前浏览器的 localStorage，不写入 URL 或日志。刷新时先确认账户，再恢复对应房间；跨标签页登录/退出会同步，所有有身份的命令带预期账户 ID，由服务器阻止身份漂移。

账户和头像存入后端 SQLite，重启后保留。退出撤销当前账户会话并清理本页的房间凭证；重新登录后仍可用房间号恢复自己的座位。

普通命令携带 `expected_version`，失败后读取最新状态，让玩家决定是否继续；不自动重发摸牌/出牌，防止网络结果不确定时重复执行。过期的轮询和恢复响应不能覆盖新牌桌或清除新会话。

## 结构

```text
src/
  App.svelte              账户、房间大厅、恢复与主题协调
  lib/account/            账户 API、验证、请求生命周期
  lib/http.ts             共享 HTTP、Cookie 与错误映射
  lib/components/GameScreen.svelte  牌桌、UNO 与房间面板协调
  lib/components/         SVG 卡牌、玩家、手牌、牌桌、原生 dialog 和面板
  lib/game/types.ts       后端 DTO 与可出牌提示（最终由服务器判定）
  lib/game/rules.ts       通用规则目录、选项依赖与建房请求
  lib/game/api.ts         HTTP、超时、错误边界
  lib/game/online.ts      联机同步、版本与请求取消
  lib/game/bootstrap.ts   会话恢复的生命周期保护
  lib/game/session.ts     本地凭证存储
  lib/theme.ts            主题偏好、系统配色与浏览器外观同步
  lib/motion/dialog.ts    可中断的弹窗动画与生命周期
  styles/                 共享视觉与动效样式
```

无运行时 UI 组件库、游戏引擎、远程字体或位图依赖。默认头像、图标、牌面均为本地 SVG；自定义头像由后端提供规范 PNG。前端从 GET /api/v1/rules 读取模块、默认值、布尔/整数/选择项及依赖约束；手牌高亮、可选颜色与规则说明来自服务端。增加现有效果协议内的后端 JSON 规则无需修改或重新构建前端。目录变化时自动读取新配置，用户确认后重新创建；读取失败仍可加入已有房间。

## 检查和构建

```sh
npm run check
npm test  # 每个测试文件启动独立真实 Go 后端与临时 SQLite
npm run format:check
npm run build
npm run preview
```

`npm test` 默认从相邻 `../unour` 构建后端，可用 `UNO_BACKEND_DIR=/path/to/unour` 指定源码；也可以用 `UNO_TEST_ORIGIN=http://127.0.0.1:8088 npm test` 连接已启动的真实服务。各测试文件的服务与登录限流独立，使用随机端口，结束时自动停止并删除临时数据库；连接已有服务时会创建带随机用户名的测试账户。

构建产物是 `dist/` 静态文件。测试覆盖请求认证与版本、人机创建请求合同、网络错误不重复发送、UNO 窗口与罚牌幂等、迟到状态保护、恢复请求隔离、叠加提示、主题偏好、弹窗动画中断、账户请求竞态，以及真实 HTTP 注册/登录/头像/真人开局、人机配置校验与电脑行动、隐私和注销。

部署时将 `dist/` 放入静态站点，并将 `/api/` 原样反向代理到 Go 服务；配置后端允许该站点的完整 Origin。同站点分域部署可在构建时设置 `VITE_API_ORIGIN=https://api.example.com`，同时配置后端允许前端来源；Cookie 为 SameSite=Lax，完全跨站的 API 应通过前端同源代理接入。生产通过 HTTPS 服务，并在 TLS 反向代理后的 Go 服务设置 `UNO_SECURE_COOKIES=true`。

前端不创建或迁移数据库；房间和游戏数据由 Go 后端 SQLite 保存。本仓库不关联后端 Git remote。

管理后台仅从 `/admin` 访问，使用独立 HttpOnly 会话和 CSRF 校验。房间页支持统计、成员名称/房间号搜索、筛选排序、本页多选永久删除，以及锁定加入和移出真人成员；详情可查看与编辑手牌。删除确认固定本次选择的房间实例和阶段，逐项显示结果，不自动重试写请求。管理配置和 API 约定见后端 `docs/admin.md`，前后端应一同升级。
